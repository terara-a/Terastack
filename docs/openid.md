# OpenID Foundation の仕様収集

公式入口は https://openid.net/developers/specs/ です。一覧の主リンクと明示された版付きリンクから `https://openid.net/specs/*.html` を検索語や仕様名で絞らず収集します。公式ホストのhttp表記はHTTPSへ正規化し、HTTPでは接続しません。説明中の参照リンクは独立した仕様として取り込みません。掲載前の編集草稿、GitHubリポジトリ、外部サイトの仕様はこの段階の対象外です。未知の名前も公式一覧にリンクが追加されれば検知します。

## 日次処理

既存の **Daily standards discovery** の `daily` / `backfill` モードで収集します。`evaluate` ではアクセスしません。スケジュールは毎日07:23（日本時間）で、実行時刻はGitHubの混雑状況により前後します。OpenIDの取得はIETF収集後に開始し、さらに最初のアクセスを30〜180秒ランダムに遅らせます。

1. robots.txtを取得してアクセス許可・Crawl-delay・Request-rateを確認します。404の場合だけ制限指定なしとして扱い、その他の取得失敗では収集を止めます。
2. 公式一覧を条件付きGETで確認し、仕様URL・タイトル・公開段階・URL上の版を更新します。公開段階は階層見出し・aria-labelledbyで結び付いたアコーディオン見出し・その版の明示ラベルから読み取ります。説明文や別の版のラベルは流用せず、読み取れない場合はOtherとします。「Implementer’s Draft」などの版付きリンクには同じ項目の主タイトルを対応付けます。一覧が空、またはHTML構造が変化してリンクを抽出できない場合は既存データを残して失敗します。
3. 本文は最大20件を直列で取得します。未取得の版を優先し、その後は前回確認が古い順に巡回します。新しい版付きURLは日次一覧で検知しますが、同じURLの本文変更は次の巡回で検知します。本文がN件なら通常は約ceil(N/20)回の実行で一周します。
4. SHA-256で本文変更を検知します。ETag / Last-Modifiedがある場合は条件付きGETを送り、304ならハッシュを維持します。

## 先方への負荷

- 並列リクエストを行いません。応答の完了から次の要求まで最低5秒＋0〜5秒のランダムな待ち時間を入れます。robots.txtが指定する間隔の方が長い場合はそちらを採用します。
- 通常は1回あたり最大22要求（robots.txt・一覧・本文20件）。リダイレクトも同じ待ち時間を適用し、合計30要求を上限にします。別ホストや収集対象外のパスへのリダイレクトは追いません。
- 429 / 503を受けたらその場で再試行しません。Retry-Afterの秒数・HTTP日時を読み、`notBefore`として保存します。次回の実行も期限前ならHTTP要求を出しません。指定がなければ24時間待機します。
- User-AgentはリポジトリURLを含むTerastackです。1応答の上限は2 MiB、タイムアウトは30秒です。
- Actionsの既存concurrency設定で同じワークフローの実行が重ならないようにします。ローカルでの多重起動は行わないでください。

## 保存・表示

保存先は `catalog/openid.json`。仕様URLごとのタイトル・公開段階・版・ハッシュ・HTTPキャッシュ情報・確認日時を保存します。本文や日次の全文コピーは保存しません。確認日時などの小さなチェックポイントは各実行で更新しますが、本文の履歴ファイルは作りません。パーサーの版が変わった場合は、以前の一覧ETag/Last-Modifiedを使わず一覧を取得し直し、古い抽出結果を持ち越さないようにします。一覧から消えた仕様も削除せず `listed: false` として保持し、現在のPages一覧から外します。

取得失敗時は成功チェックポイントを進めません。429 / 503の待機期限だけは次回の負荷抑制のため保存します。失敗した実行のデータPRは自動マージせず、次回実行で待機期限を含む保留中のデータを復元します。

Pagesでは出典でIETF / OpenID Foundationを絞り込めます。OpenIDは「公式一覧掲載・未確認」と公開段階を表示します。`catalog/reviewed.json` に原文の確認結果を登録すると、対象URL・版・本文ハッシュが一致する間は確認済みになります。変更時は再確認待ちに戻し、本文の取得日時と原文の確認日時を区別して表示します。[確認結果の登録手順](reviews.md)を参照してください。公式一覧の全仕様を掲載し、IETF用の意味分類には投入しません。

## ローカル確認

追加のPythonパッケージやAPIキーは不要です。

```sh
npm run test:openid
npm run collect:openid
npm run build:pages
```

`collect:openid`は実際のアクセスと待ち時間を伴います。通常の開発では通信しないユニットテストを使ってください。

2026-11-11に公式サイトでrobots.txt・一覧・本文3件の取得と、本文の条件付きGETによるHTTP 304を確認しました。保存した一覧を修正後のパーサーで再検証した結果、主リンク・版付きリンク87件を抽出し、スキーマ検証とPagesビルドが成功しています。公開段階の内訳はFinal 39件、Implementer's Draft 44件、Draft 2件、Other 2件です。修正時の検証は保存済みHTMLを再生し、追加の外部アクセスを行っていません。

実サイトの該当構造を縮小した回帰テストを `collector/fixtures/openid-listing.html` に含めています。別のクラウド環境から接続する場合は許可ドメインに `openid.net` が必要です。GitHub Actionsはこのクラウド環境の許可リストを使用しません。
