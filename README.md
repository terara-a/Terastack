# Terastack

認証・認可の標準を追跡するカタログと Cloudflare Workers 用サンプル。

## 開発

Node.js 24 以上。既存チェックアウトを使用します。

```sh
npm test
npm install
npm run dev
```

`POST /examples/pkce` に JSON `{"verifier":"43〜128文字のRFC 7636 verifier"}` を送ると S256 challenge を返します。RFC 7636 Appendix B のベクトル、入力拒否、HTTP 応答をテストします。これは認可サーバーではなく、仕様の一部分の学習用サンプルです。秘密値を送信せず、ローカルで利用してください。

Workers の Fetch / Web Crypto のみを利用します。`wrangler.jsonc` を使って将来 Workers にデプロイできます。現在のテストは Node の Web API によるもので、workerd 上での検証や Cloudflare へのデプロイはまだ実施していません。

## 新しい規格の発見

```sh
npm run collect
FULL_SCAN=true npm run collect
```

Datatracker の RFC・Internet-Draft メタデータを、検索語や WG で絞らず取得します。初回は全件、ドラフトは通常3日の重複期間を含む差分取得、日曜日は全件照合です。RFC は番号順に公開されるとは仮定せず、毎回一覧を全件照合して未取得番号を検出します。取得中のメタデータはメモリ上でのみ扱い、概要や API 応答の丸ごとは Git に残しません。RFC の既存本文・分類は日次更新せず、正誤表や更新関係の追跡は別途実装予定です。

### 保存するもの

- `catalog/state.json`: 全件の軽い索引。文書名ごとに `[版, 更新日時, 判定, 分類器の版?, 最終分類試行日時?, 新規・更新検出日時?]` を保存。判定は `true` / `false` / `null`（未判定・判断困難）。RFC の版・日時は空文字で、番号と判定を保持します。最大番号だけを境界にしないので、遅れて公開された小さい番号も拾えます。
- `catalog/related.json`: 関連あり文書だけのタイトル・版・URL・判定理由。未判定候補は索引に残り、除外されません。
- `reports/daily/`: 実際に変更のあった実行の集計と関連文書 ID。概要・文書全体・未判定リストは複製しません。変更のない実行ではチェックポイントもレポートも書き換えず、PR を発生させません。その場合、次回も最後に変更があった取得時刻から重複取得します。

ドラフトの新版・メタデータ更新時は旧判定を未判定に戻し、関連カタログからいったん外して再確認します。索引は最新版だけを保持し、将来サンプルが依存する過去版の固定は別途管理します。RFC の関係・正誤情報はこの索引の対象外です。

### 分類と日次処理

分類対象の概要は必要時に公式 API から再取得します。日次は新規・更新文書を優先し、残りの枠で未処理の既存文書を分類します。判断困難な候補の再試行は7日後です。初回分は別の `backfill` モードで小分けに再開できます。処理済みの関連・非関連判定を再課金しません。

モデル設定・少量評価・初回分類の手順と費用上限は [分類の運用手順](docs/classification.md) を参照してください。初期の累積予約額上限は **USD 0.10**。API未設定時は収集を続け、有料リクエストは送りません。設定後はモデル一覧から対応候補を自動選択し、モデル変更時は少量評価を自動でやり直してから分類します。

Actions は毎日22:23 UTC（日本時間翌日07:23）に実行します。リポジトリで Actions の PR 作成を許可してください。最新の main のコードで動作し、未マージの日次ブランチからはカタログとレポートだけを引き継ぎます。

### 旧データの移行

```sh
node collector/migrate.ts
```

旧形式の全件データを軽い索引へ、旧日次レポートを集計へ変換します。文書 ID と最新の判定は保持し、API メタデータの複製は除去します。繰り返し実行しても同じ結果です。過去の原データは Git 履歴に残ります。**今回の変更は今後のツリーと増加量を軽量化し、既存 Git 履歴のサイズは削減しません。**

## 現在の範囲と次の段階

実装済み: RFC・ドラフトの全件/差分発見、意味による概要分類、未判定レビューキュー、日次カタログ PR、PKCE サンプル。

未実装: 公式本文の版別保存・ハッシュ、節単位差分、RFC Editor の Updates/Obsoletes/Errata の照合、参照先探索、除外判定の定期再分類、JWT/DPoP サンプル、LLM による日次のコード生成。分類の網羅性は保証できません。

## GitHub Pages

収集状況・関連仕様の検索・最近の収集履歴・ブラウザ内のPKCEデモを静的ページとして公開できます。分類が未完了の場合も、未判定件数と空の関連一覧をそのまま表示します。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します（管理権限が必要）。
2. Pages対応の変更をmainへマージします。
3. Actionsの **GitHub Pages** が成功すると、デプロイジョブのURLから開けます。設定後の再実行はRun workflowからも可能です。

mainへの更新ごとにサイトを再生成します。収集結果は更新PRをマージした後に反映されます。PRではビルド検証だけを行い、デプロイしません。

```sh
npm run test:pages
npm run build:pages
python3 -m http.server 8000 --directory dist
```

`site/` はHTML/CSS/JavaScript、`scripts/build-pages.ts` は公開データの生成処理です。公開物は `dist/` の静的ファイルだけです。全件索引・費用台帳・API応答・キーは配信せず、件数と関連文書の許可した項目だけを `data.json` に書き出します。パスは相対指定なので `/Terastack/` などのプロジェクトページでも動きます。外部のフォントやJavaScript CDNは使いません。

静的サイトの公開はモデルAPIの課金・分類・Workersのサーバー実装とは独立しています。認可サーバーや状態を持つサンプルは引き続きWorkers等で実行します。
