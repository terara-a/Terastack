OAUTH 2.0 / RFC 6749 + RFC 7636

認可コードと verifier を、
結びつける。

PKCE が効くのは、認可要求で渡した challenge と、コード交換時の verifier を認可サーバーが照合する時です。

このページはブラウザ内のシミュレーションです。通信境界・ログイン認証は再現していません。実際の HTTP フローを動かす Workers コードと実行手順を別ページに用意しています。

CLIENT

クライアント

verifier と state を生成・保持し、戻った state を確認してからコードを交換。

AUTHORIZATION SERVER

認可サーバー

コードに challenge・client_id・redirect_uri を紐付け、交換時に照合。

RESOURCE SERVER

リソースサーバー

アクセストークンを検証して、許可されたリソースを返す。

順番に実行する

1. 認可要求を作ってください。

認可コードの有効期限は5分、トークンは10分。許可する主体は固定の demo-user です。リセットするとこのページ内の記録を破棄します。

拒否される条件を試す

verifier 不一致は認可サーバーで拒否。state 不一致はクライアントで止め、token 要求を送りません。正しく交換できたコードは二度使えません。

クライアント内に保持する値

verifier は認可要求へ送らず、コード交換時にだけ送ります。state は往復させて照合する別の値です。
